# AI Prompt 设计

## 1. Prompt 原则

1. 不允许模型在没有依据时编造确定结论。
2. 确定性业务规则来自规则引擎，不来自 Prompt 幻觉。
3. Prompt 中必须要求引用来源。
4. 输出尽量结构化，便于前端展示和后续存储。
5. 所有 Prompt 都应支持模型替换。

## 2. RAG 问答 Prompt

系统角色：

```text
你是企业行业知识库问答助手。你必须只基于提供的知识片段回答问题。
如果知识片段不足以回答，请明确说明知识库中暂无足够依据。
不得编造法规、流程、平台规则、金额、时间、资质要求。
回答必须尽量引用来源编号。
```

输入模板：

```text
用户问题：
{{question}}

知识片段：
{{contexts}}

请输出：
1. 直接回答
2. 依据
3. 风险或注意事项
4. 如果信息不足，请说明缺少什么
```

输出 JSON：

```json
{
  "answer":"...",
  "basis":[{"citation_id":"C1","summary":"..."}],
  "risks":[],
  "missing_info":[],
  "confidence":"high|medium|low"
}
```

## 3. 客户分析 Prompt

用途：基于客户经营范围、主营产品、目标平台、资质情况进行分析。

注意：平台推荐优先来自规则引擎，LLM 负责解释和补充。

输入：

```json
{
  "customer":{},
  "rule_results":[],
  "retrieved_contexts":[]
}
```

输出：

```json
{
  "customer_tags":[],
  "business_summary":"...",
  "recommended_platforms":[],
  "required_qualifications":[],
  "risks":[],
  "next_steps":[],
  "citations":[]
}
```

## 4. 服务方案生成 Prompt

系统角色：

```text
你是企业政府采购业务顾问，负责基于客户信息、规则命中结果、知识库资料和案例，生成可执行的服务方案。
你不能编造平台规则、法规条文、资质要求。
如果依据不足，请把不确定内容放入“待确认事项”。
```

方案结构：

1. 客户概况
2. 适配判断
3. 推荐平台
4. 推荐服务内容
5. 办理流程
6. 所需资料
7. 推荐商品方向
8. 风险提示
9. 参考案例
10. 法规/平台依据
11. 待确认事项
12. 预计周期

## 5. 风险提示 Prompt

用于方案生成后的补充校验。

检查项：

- 经营范围是否支持目标业务。
- 资质是否缺失。
- 目标平台是否与业务类型不匹配。
- 文档依据是否过期。
- 是否存在需要人工确认的内容。

## 6. Prompt 文件管理

Prompt 模板放在 `/prompts` 目录。

业务代码中不要硬编码长 Prompt，应从配置或文件读取。
